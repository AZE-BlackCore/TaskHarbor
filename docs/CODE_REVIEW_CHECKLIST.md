# 代码审查检查清单

## 🔴 阻塞性问题（必须修复）

**任何一项为"否"，必须修复后才能合并**

### 安全性
- [ ] 无 SQL 注入风险（数据库查询使用参数化）
- [ ] 无 XSS 攻击风险（用户输入已转义）
- [ ] Electron 渲染进程未启用 `nodeIntegration`
- [ ] Electron 启用了 `contextIsolation`
- [ ] IPC 消息处理有输入验证
- [ ] 敏感信息（密钥、密码）未硬编码
- [ ] 文件操作验证了路径合法性

### 正确性
- [ ] 代码逻辑正确，能实现预期功能
- [ ] 所有异步操作有错误处理（try-catch 或 .catch）
- [ ] 无未处理的 Promise rejection
- [ ] 边界情况已处理（空值、null、undefined、空数组）
- [ ] 数据库事务使用正确（多步骤操作）

### 数据完整性
- [ ] 关键数据操作有验证
- [ ] 外键约束正确处理
- [ ] 并发操作无竞态条件
- [ ] 数据删除考虑了级联关系

### 性能

- [ ] 无明显的内存泄漏风险

## 🎯 使用说明

### 如何使用此清单

1. **打印清单** - 每次审查前打印一份
2. **逐项检查** - 仔细阅读代码，对照清单检查
3. **标记问题** - 对不符合的项打"×"，符合的打"✓"
4. **记录意见** - 在审查意见区写下具体反馈
5. **给出结论** - 在审查结论区选择审查结果
6. **归档保存** - 审查完成后扫描或拍照归档

### 审查时间建议

- **小型变更**（< 200 行）：15-30 分钟
- **中型变更**（200-500 行）：30-60 分钟
- **大型变更**（> 500 行）：60-90 分钟（建议拆分）

### 审查最佳实践

✅ **专注** - 审查时不要分心，专注代码质量  
✅ **耐心** - 仔细阅读每一行变更的代码  
✅ **建设性** - 提出问题的同时给出改进建议  
✅ **平衡** - 关注重要问题，不要过度挑剔  
✅ **学习** - 从他人的代码中学习优点
