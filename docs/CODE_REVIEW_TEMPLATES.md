```

```

**使用示例：**

```markdown
🔴 **阻塞：安全 - SQL 注入风险**

**位置：** `main/src/services/task-service.ts: 42`

**问题描述：**
用户输入的 `taskId` 直接拼接到 SQL 查询中。

**为什么这是个问题：**
攻击者可以注入恶意 SQL，如 `'; DROP TABLE tasks; --`，导致数据丢失。

**建议修复：**
```typescript
// ❌ 错误
db.run(`SELECT * FROM tasks WHERE id = '${taskId}'`);

// ✅ 正确
db.run('SELECT * FROM tasks WHERE id = ?', [taskId]);
```

**参考资料：**
- [SQL 注入攻击示例](https://owasp.org/www-community/attacks/SQL_Injection)

请修复后重新提交，谢谢！
```

[提供优化思路]

**好处：**
[说明优化后的好处]

```

**使用示例：**

```markdown
💭 **优化：性能 - 使用 useMemo 缓存**

**位置：** `renderer/src/views/ListView.tsx: 56`

**建议：**
```typescript
// 当前
const filteredTasks = tasks.filter(task => task.status === status);

// 优化
const filteredTasks = useMemo(
  () => tasks.filter(task => task.status === status),
  [tasks, status]
);
```

**好处：**
避免每次渲染都重新计算过滤结果，提升性能。

可选优化，时间充裕的话可以考虑~
```

```markdown
# 新成员代码审查指南

欢迎加入 TaskHarbor 团队！这是你的代码审查指南。

## 📚 第一步：学习审查标准

请阅读以下文档：
1. [代码审查标准与流程](./CODE_REVIEW_STANDARDS.md)
2. [审查检查清单](./CODE_REVIEW_CHECKLIST.md)
3. [审查模板](./CODE_REVIEW_TEMPLATES.md)

## 👀 第二步：观摩审查

**任务：** 阅读最近 5 个已合并的 PR 审查记录

**关注点：**
- 审查者提出了哪些问题？
- 问题是如何分类的（阻塞/建议/优化）？
- 审查评论的语气和格式？

## ✍️ 第三步：实践审查

**第一次审查：**
1. 选择一个简单的 PR
2. 使用 [审查清单](./CODE_REVIEW_CHECKLIST.md)
3. 写下你的审查意见
4. 与资深审查者讨论

## 💬 审查沟通技巧

✅ **应该做的：**
- 具体明确地描述问题
- 提供改进建议和代码示例
- 使用建设性的语气
- 表扬优秀的代码

❌ **不应该做的：**
- 对人不对事
- 使用模糊的批评
- 只提问题不给建议
- 过度挑剔细枝末节

## 🎯 常见问题

**Q: 如何判断问题是阻塞性还是建议性？**

A: 问自己：如果这个问题不修复，代码能安全上线吗？
- 不能 → 阻塞性
- 能，但有风险 → 建议性
- 纯粹优化 → 优化建议

**Q: 审查需要多长时间？**

A: 根据 PR 大小：
- 小型（< 200 行）：15-30 分钟
- 中型（200-500 行）：30-60 分钟
- 大型（> 500 行）：60-90 分钟

**Q: 发现太多问题怎么办？**

A: 优先处理阻塞性问题，建议性问题可以分批提出。
